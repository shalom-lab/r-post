# R语言师兄脚本换台电脑就挂：用 renv 锁住包版本
RPost
2026-10-07

师兄把分析项目拷过来：脚本能打开，一 `library`
就报缺包；装齐之后，同一行 `dplyr`
代码结果又和师兄截图差一截——两边包版本不同。`renv`
在项目里写一份锁文件，记下当时用过的包名和版本，换机器时按锁安装。

下文 `renv::*`
调用都不在渲染时执行（换机器才需要真跑）；只读展示锁文件长什么样。

## 三步：init、snapshot、restore

在项目根目录：

``` r
# 1. 给当前项目建 renv 脚手架（生成 renv/ 与 renv.lock 雏形）
renv::init()

# 2. 包装好、脚本能跑通后，把依赖写入 renv.lock
renv::snapshot()

# 3. 换电脑或换目录：打开项目后按锁文件安装
renv::restore()
```

`init()`
之后，打开这个项目会优先用项目库，少和全局库搅在一起。`snapshot()`
扫描你用到的包，写入 `renv.lock`。同事或半年后的自己执行
`restore()`，按锁安装同一套版本。

锁文件是 JSON，开头大致像这样（示意，版本号随你机器而变）：

``` r
# renv.lock 片段示意
# {
#   "R": { "Version": "4.3.2", ... },
#   "Packages": {
#     "dplyr": { "Package": "dplyr", "Version": "1.1.4", ... },
#     ...
#   }
# }
```

把 `renv.lock` 和脚本一起纳入版本管理。`renv/`
目录里的库文件很大，一般不整目录提交；按 `renv` 文档把该忽略的写进
`.gitignore`。

## 它管不到什么

`renv.lock` 会记下生成锁时的 **R 版本**，但 `restore()`
**不会**帮你重装或切换 R 本身。同事仍是 R 4.2、你是
4.4，包即便版本相同，也可能有行为差别。需要同一 R
时，要自己对齐安装，或在容器镜像里固定
R——容器方案一句带过即可，本文不展开。

随机数也不只由包版本决定。例如 `sample()` 的算法在不同 R
版本间改过；只锁包、不锁 R，模拟结果仍可能对不上。要可重复模拟，固定
`set.seed()`，并写明 R 版本；关键结果不要假设「有 lockfile
就字节级一致」。

## 和「分析存档」怎么分工

`renv` 锁的是**包环境**。模型对象、中间表、整次会话，仍用 RDS / `save` /
Excel 等保存。五种常见存法见
[分析做到一半如何存临时数据](../20260921-r-save-five-methods)：环境用
`renv`，数据用那五法里合适的一种，各管一段。

换机器先 `restore()`，再打开脚本；R 版本和随机数算法要自己另对齐。
