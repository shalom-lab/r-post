# Post-content 检查（入库前必做）

成稿默认可直接写入 `content/posts/`，不必强制先 `.drafts/`。**推仓库前须通过本检查**；未通过先改到过再推。  
这一步不可省略、不可与「随便扫一眼」合并掉。人和 Bot 共用。

## 何时做

成稿正文（接近最终 QMD）写完后、**写入仓库 / 推送之前**。未通过则改稿后重做本检查，不得带病入库。

## 检查清单（逐项过）

### 1. 去 AI 味
成稿中文按 **qu-ai-wei** 习惯过一遍（技能 `[去 AI 味](sand-workflow:ai-qu-ai-wei)` / 仓库外约定）：锁住数字、术语、判断与责任关系；清套话、机械对称（尤其反复的「不是 X，而是 Y」）、翻译腔与空转连接词；不编造原文没有的观点或细节；技术文不降格成闲聊。
- 删掉空话套话：数字化时代、本文将带你、轻松掌握、综上所述、值得注意的是（无信息增量时）。
- 语气像同事当面讲一个操作，不像说明书或模型总结。
- 不堆同义反复、不每段强行「你」「我们」。
- 标题与小标题口语、具体；不像目录名或论文小标题。

### 2. 场景与分镜是否「常用」
- 每个情景 / 分镜必须是数据分析里**真会反复碰到**的小任务（批量读表、编码识别、规则提取字段、批处理、保存中间结果等）。
- **不常用、偏门、强行专业示意**的分镜要换掉或改成更日常的等价任务（例如：少用冷门编码区间硬示意，改成同事更常搜的关键词 / 固定格式字段 / 批量文件名）。
- 一篇只办一类事；分镜是同一本事的多个常见切口，不是凑数。

### 3. 结构与风格
- 符合 `writing-style.md`：先情景再方法；对照升级或一分镜一场景。
- 代码最短路径能跑；不编造未执行的数字与结论。
- 若引入新 R 包，同步核对 `render.yml`（见 `AGENTS.md` 提交前依赖检查）。


### 3.5 R 代码：无必要不要创建中间变量
- 能一步写清（管道、嵌套、直接 `files[grepl(...)]`）就不要先赋值再只用一次。
- **允许**中间变量：要展示/讲解中间结果、复用 ≥ 2 次、拆开明显更好懂。
- **不鼓励**一次性跳板（如只用下一行的 `kw_pattern`、`ok`、`xlsx_sales`）。

### 3.6 主题深度与结构（评审会盯技术细节）
写稿 / 改稿时自问并写进检查交代：
- 这篇主题**该讲什么**、深度到哪一层（讲清 1～3 个重点即可，不碎不浅）？
- 行文是否顺着：**场景 → 最小可跑代码 → 常见坑 → 可选扩展**？
评审打回常点名段落 / 代码，并给「现在怎样 / 为何不好 / 建议改成怎样」——按**同粒度**吸收改稿，不要只等宽泛点评或只改措辞。

### 3.7 已生效的其它硬关（一并自检）

- 人话标题：念给外行听约 3 秒能懂。
- 白话用词（如「提取数据」，不用站内黑话「扣数据」）。
- qu-ai-wei：去机械对称与空转套话。
- 场景可跑：内联或仓库内可跟随的数据，读者能验收输出。
- 禁用硬造口语（全站）：「真活」「真活里」「踩两脚」、「踩坑」（作动词腔）、「心里有数即可」；另禁「落盘」「要落盘时」「中途落盘」「整现场」「一键」（营销腔）、「落地」「闭环」「抓手」「颗粒度」「赋能」「丝滑」「开箱即用」。小节标签「坑：」可保留。改成平常说法（实际整理数据时 / 真实数据里常见… / 这里不展开演示；「存一下」「要存数据时」「整个工作区」等）。
- **硬造口语要举一反三**（固定习惯，不只改被点名的那一个）：
  1. 用户或自检点出一个词时，不是只改这一处，而是同段、同篇、全仓扫一遍同类腔（产品腔、假口语、营销腔的兄弟词）。
  2. 自测：念给同学听，正常人会这么说吗？不会就换平常说法。
  3. 新词立刻补进上面的禁用清单；改完在仓库根目录 `git grep`，除清单本身外应为 0；改了 qmd 要等 Render 生成的 `.md` 落地再说对齐。
  4. 成稿检查时主动跑一遍禁用词 grep，不要等用户点名；发现一个可疑词，先想「还有哪些兄弟词」。


### 3.8 作图须达科研发表级（含 ggplot 及同类）
凡正文出图（`ggplot2`、base 绘图、lattice 等），**不能只满足「能出图」**；须达到科研发表级美观，品控按此审，丑图会打回并点名改法。

自检至少包括：
- **主题干净**：不用默认灰底凑合；优先浅色白底或克制主题（如 `theme_minimal()` / `theme_bw()` 再微调）。
- **字体可读**：中英文轴标签、图例、标题清楚；CI/本机若缺中文字体，轴标签可用英文并在正文说明中文含义，勿交付方块字或乱码。
- **配色克制**：色数少、对比够；色盲友好优先；别堆彩虹默认盘。
- **信息完整不挤**：坐标轴标题、必要图例/标注齐全；线型与颜色有明确区分（需要时图内图例或 `annotate`/`geom_text`）。
- **边距与宽高比**：YAML/`fig-width`/`fig-height` 合适，关键元素不贴边、不裁切；缩略仍可读。

成稿检查时主动打开 Render 出的图看一眼：像不像论文/正规报告里能贴的图？不像就改代码再推。

### 4. 通过标准
- 清单无未处理红灯。
- 需要人拍板的疑点（算不算「常用」、标题语气）先请示，再写入仓库。
- 通过后才：写入 QMD →（如需）回写 `topics/index.json` 的 `article` → 推送；之后交给 Render / Pages。

## 产出形式（对话里）

检查时至少交代：
1. 改了哪些 AI 味；
2. 哪个分镜 / 例子因「不常用」被换掉或保留的理由；
3. 一句结论：`检查通过，可以入库` 或 `未通过，还要改……`。
