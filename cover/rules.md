# RPost 封面设计规范

流程见 `AGENTS.md`。由 Codex 先读文章，再构思并使用内置 imagegen 制作。**风格不设限，每张都要美观、清晰、贴合文章。** 下列参考用于理解用户认可的质量，不是固定模板。

## 先理解文章

读完整篇 QMD（缺失时读 Markdown），弄清读者正在处理什么材料、遇到什么问题、文章如何解决、最后得到什么。选一个最有代表性的场景或机制作为主视觉，不把全部章节塞进封面。

标题用具体、白话的表达，可压缩原文章名，不歪曲含义、不夸大效果。视觉元素应能解释本篇内容；可以直接呈现文件、表格、文本片段，也可以用贴合机制的隐喻。

## 设计自由与质量要求

- 按文章选择合适的风格：纸感立体插画、平面设计、编辑插画、摄影感、拼贴、简洁信息图等均可，也可以探索其他形式。
- 不固定米白背景、宋体、配色、左右布局、物件数量或冲突结构。选择一种清晰的视觉语言，避免无目的地混搭。
- 保持明确的信息层级：主标题醒目，一个视觉中心，辅助文字适量。函数名或小表格只有在帮助理解时才加入。
- 构图平衡、留白合理、字体和主题协调、配色有节制。装饰服务内容，不靠堆图标、代码或特效填满画面。
- 主标题在 900×383 的显示尺寸下仍应清楚。关键内容留足安全边距，避免贴边或依赖裁切才能成立。
- 同系列可以保持呼应，也允许不同文章采用不同风格。用户对某张图有明确要求时优先遵从。
- 默认每篇直接做一张完成度高的封面，不为了展示风格数量增加无必要的候选和选择步骤。

## 主动尝试不同风格

用户明确希望多尝试。后续制作时主动探索不同设计，不因某一张获得认可就长期重复同一种模板。读完文章后考虑几种方向，再选择最适合本篇的一种直接制作；不要求每次让用户先选风格。

用户进一步明确“天马行空，各美其美”：Excel 批读封面是完成度参考，不是强制视觉参考。按清单逐篇制作时，每篇独立构思；主动拉开字体、构图、色彩、材质和表现手法的差异，不默认传入该图作为参考，也不把所有封面统一成纸感系列。

- **YouTube 缩略图方向**：强对比、大标题、主体特写、清楚的前后变化或悬念，适合具体问题与结果对比；吸引力来自正文，不编造夸张结论。
- **小红书方向**：可尝试杂志排版、手账拼贴、笔记卡片、清爽生活感或醒目的知识封面，适合经验与实用技巧；不限定为粉色或固定贴纸模板。
- **其他方向**：摄影、复古印刷、极简字体海报、漫画、立体插画等都可探索，按文章内容决定。

借鉴平台的视觉表达，不照搬平台截图、标识或常见尺寸。所有风格仍适配默认 1800×766 横版，保证标题和关键内容清楚。风格变化应体现在构图、字体和表现手法上，不只是换背景色；每次交付仍须达到美观、贴题、易读的要求。

## Prompt 应包含什么

每篇独立编写，具体描述以下内容即可：

1. 用途与尺寸：公众号文章横版封面，一张完整成图，目标 1800×766、约 2.35:1。
2. 内容依据：文章的具体场景、关键操作和结果，以及本次选取的视觉例子。
3. 文字原文：逐字指定标题、可选副标题和函数标签，说明层级与断行。
4. 画面关系：主体、连接或对比如何对应文章；出现具体数据时写清数值及对应关系。
5. 本篇风格：选择的字体气质、配色、构图、材质或表现手法，保证整体协调、缩小可读。
6. 必要约束：文字与数字准确，无水印，不添加无关口号、代码墙或多图拼版。

例如提取篇：“从 `随访_华东_202409.xlsx` 中突出 `华东` 与 `202409`，分别连接到地区、年月两列，与表格首行严格对应。”捕获标记若作为注释出现，不能让人误以为文件名本身含有额外括号。

`cover.json` 的 `prompt` 保存实际发送的完整提示词，不用规则全文或事后总结代替。

## 成图核验

- **尺寸**：默认实际交付文件为 1800×766；用户另有要求则遵从。检查实际像素，不把提示词中的要求当作已达成。
- **美观与可读性**：整体协调，主体明确，留白得当；按 900×383 查看，标题仍清晰，辅助信息不过密。
- **文字准确**：中文无错漏，函数名、下划线、括号、数字和符号正确。
- **内容准确**：颜色、箭头和数据对应同一例子；筛选与提取等不同操作不能混淆，不暗示正文没有的能力。
- **画面完整**：无水印、无意外拼版，标题和关键图形未被裁掉，背景与阴影不妨碍阅读。
- **登记正确**：成品存在、格式与扩展名一致、实际 prompt 已记录，合格后再启用清单条目。

发现问题就针对性修正并复查，达到可交付质量后直接完成。用户要求调整时继续迭代。
