# 封面作图要点

出图前读本文件。流程见 `cover/AGENTS.md`。

一 `id` 出**一张大图**。不管小图。最终入库须为约 **2.35:1** 横图，清晰度 **至少 1800×766**（豆包直出常见 ~3008×1280，比例对则原样保留）。

**出图强制**：用**豆包 Seedream**（优先 4.5）在「新对话」里直出横版封面。  
**禁止**再用 `GenerateImage` / 16:9 蒙版裁切出封面。

---

## 一、通用要求（尺寸 / 底线）

### 成品

- **合格尺寸**：比例约 **2.35:1**，像素 **≥1800×766**（更大且比例对的原图保留）。
- 流程：提示词写死约 2.35:1 → **控制台高清无水印下载** → **一律**跑 `node scripts/crop-cover-235.mjs cover/images/<id>.jpg`。
  - 已 ≥1800×766 且比例约 2.35:1 → 脚本整段跳过（保留更高清）
  - 比例已约 2.35:1 但偏小 → **不裁构图**，只压/放到 1800×766
  - 比例差太多（其他模型 16:9 等）→ 居中裁再压到 1800×766

### 豆包出图参数（写进提示词）

在提示词正文里写死：

- `比例 2.35:1，成品至少 1800×766（可更高），横版封面，无水印`
- `只出 1 张终稿，不要中间稿、不要多图拼版`
- 画面文字用**简体中文**；若必须出现 R 函数名，按正文原样（如 `all.equal`、`save.image()`），禁止乱改成 `all_equal` 之类

### 下载（强制无水印）

- **必须**用 F12 控制台脚本拿原图，不要点页面「保存」凑合（页面下载常带「豆包AI生成」水印）。
- 用法：`window.__DOUBAO_DL__ = { PREFIX: "<id>", EXPECT: 1 }`，再粘贴 `/workspace/bot-doubao/scripts/doubao-zip-download-hd.js`（只扫当前 `/chat/{id}` 消息区）。
- 下载阶段**禁止**往聊天输入框粘贴脚本路径或代码。
- 粘贴进豆包后、点发送前：必须回看输入框，确认**钩子每一个字**都在（中文易被吃字）；不对就改完再发。

- 成图若仍有水印 → **不合格，重下或重出**，不得入库。

### 格式与忌项

- 成品 `jpg`；路径 `images/<id>.jpg`。
- 忌：假二维码 / 假头像墙；紫粉霓虹乱闪、玻璃拟态、乱粒子、假 3D 按钮条。
- 忌：代码墙 / 公式墙；小图拼版 / 虚线外框；钩子写错字 / 符号写丢（尤其 `==`、`.`、`()`）。
- 忌：元素堆砌、说明书式场景复现、把正文知识点一股脑画进画面。

> 旧蒙版 `templates/ref-16x9-black235-white-margins.jpg` **已停用**，勿再引用。

## 二、本项目自定义（RPost · YouTube 缩略图风）

> **目标观感 = YouTube / B 站爆款缩略图**：一眼看懂冲突，不是科普插画，更不是文章摘要拼贴。

### 核心原则（按优先级）

1. **一个钩子 + 一个比喻**：读懂正文痛点后，先想一个**生活/物理类比**（锁、裂缝、天平、迷路、掉坑……），再画。不要把 R 操作流程画成连环画。
2. **元素要少**：画面主体 **最多 2～3 件**（例如「碎电脑 vs 一把锁」）。钩子大字算一件「文字」，不要再叠一堆小标签、图标条、代码碎片。
3. **允许适当发散**：道具不必字面来自正文（不必画数据框、管道符、包名墙）；类比能讲清「麻烦 vs 解法」即可。专名只在钩子或必要的一处出现。
4. **高对比、大特写**：暖橙 vs 青绿 / 红 vs 蓝一类即可；主体占画面大部分，背景干净，少景深杂物。
5. **逻辑自洽**：左右/前后对比要说得通（坏的一侧 vs 好的一侧；崩溃 vs 稳住）。禁止无关物件硬凑。

### 要

1. **大字钩子**：短、响、对准这篇核心麻烦（一般 ≤10 字）。
2. **冲突或前后对比**（左右分屏或一前一后都行）。
3. **夸张但好懂的类比插画**（半写实 / 扁平插画均可）。

### 不要

- 把文章章节、多个函数、多个包名同时塞进画面。
- 代码墙 / 公式墙 / RStudio 整屏截图风。
- 只看标题就出 prompt；也**不要**「忠实复现正文每个例子」。
- 小图拼版、虚线外框、重复小标签、说明书式多面板。
- 为了「显得很 R」而堆 `%>%`、`ggplot`、散点图墙等装饰。

## 三、作图 prompt 怎么写（必读正文 → 再发散）

### 1. 先读推文，再提炼一句

读 `content/posts/<id>/*.qmd`（或 `.md`）。勿只看 `title`。

读完只留下三样，写进 prompt：

| 提炼 | 要求 |
|------|------|
| 痛点一句话 | 读者最烦的那个点 |
| 类比一句话 | 生活/物理隐喻，不必出现在正文里 |
| 钩子原文 | 将打在图上的短句 |

其余细节（多个函数、多个步骤）**丢掉**，不要画进图。


### 1b. 理解文章机制（举一反三，不盯标题）

读完正文后，**先写三行内部提纲**（可放 `note`，不必原样进画面），再写 prompt：

| 提纲 | 问自己 |
|------|--------|
| 痛点机制 | 读者到底卡在哪一步？（不是标题情绪词） |
| 类比映射 | 生活/物理隐喻如何一一对应「麻烦 → 解法」？ |
| 故意不画 | 文中哪些细节（步骤、边界、多包名）这次**不画**？ |

要求：

- 封面服务「一眼懂冲突」，不是复述全文；但**类比必须贴机制**，不能漂成无关事故（如本文是包版本漂移，就不要画成电脑摔坏）。
- 允许举一反三换道具，但左右两边要说得通：坏的一侧 = 机制失灵，好的一侧 = 文中解法的视觉等价物。
- 钩子优先用正文里的具体麻烦句，少用空泛感叹。


### 2. 出图方式

| 项 | 约定 |
|----|------|
| 账号 | 豆包「迷城」（或指定小号） |
| 入口 | **新对话** + 「图像生成」（禁止「新工作任务→工作」） |
| 模型 | 尽量 Seedream 4.5 |
| 张数 | 每篇 **1** 个新对话、**1** 张终稿 |
| 下载 | **仅**控制台 `EXPECT: 1` + HD zip 脚本（无水印）；禁止页面「保存」凑合 |

### 3. prompt 结构（短、少元素）

按这个骨架写，**整段控制在约 8～12 行以内**：

1. 尺寸与张数句（见上）。
2. 「YouTube 缩略图风格，高对比，主体特写，背景干净。」
3. **钩子原文**（加引号）。
4. **一个类比冲突**（只写左右/前后各 1 个主体，勿列清单）。
5. 主色一对（如暖橙 + 青绿）。
6. 否定句：「不要代码墙、不要多面板、不要小标签堆砌、不要把多个函数画进画面；元素不超过三件。」

### 4. 好例子 / 坏例子

**好**（元素少、类比清楚）：

> 比例 2.35:1，至少 1800×766，横版封面，无水印；只出 1 张终稿。YouTube 缩略图风，高对比，背景干净。大字钩子「换电脑就挂？」。左边：摔裂的笔记本；右边：一把挂锁锁住一份文件。暖橙 vs 青绿。不要代码、不要包名墙、不要第三件道具。

**坏**（堆砌、没逻辑）：

> ……左边碎电脑 + dplyr 碎片 + 散落的 csv + 终端报错；右边 renv.lock + 挂锁 + 绿色对勾 + 文件夹树 + 小标签「可复现」「团队协作」……

### 5. 出图后核验（写回前）

1. 比例约 2.35:1，且宽高至少 1800×766（或更大原图已保留）。
2. **无「豆包AI生成」水印**（有则重下/重出）。
3. 钩子可读；若有 R 专名，无改义错字。
4. 一眼能说出「冲突两边是什么」；主体不超过约三件。
5. 无色情 / 暴力 / 政治；无假二维码。
6. `cover.json` 的 `prompt` = 实际发给豆包的那条。

### 6. 写入 `cover.json` 的 `prompt`

存实际发给豆包的全文（须含 2.35:1，并写清至少 1800×766）。
